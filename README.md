# 德州扑克练习 · Texas Hold'em Trainer

一个**纯前端、单机、可离线运行**的无限注德州扑克（No-Limit Texas Hold'em）现金局练习游戏。你与多个性格各异、可被长期观察的 AI 对手同桌对战，并配有实时胜率、决策复盘、手牌回放等学习辅助面板。

- 技术栈：**React + TypeScript (strict) + Vite + Zustand + Tailwind CSS**
- 零后端、零部署，刷新不丢数据（localStorage 持久化）
- 核心算法（牌型评估、边池分配、蒙特卡洛、赔率）均配 **Vitest 单元测试**

## 快速开始

```bash
npm install      # 安装依赖
npm run dev      # 启动开发服务器 (默认 http://localhost:5173)
npm run dev:host # 开发服务器并暴露局域网地址 (供 iPad/手机访问)
npm run build    # 生产构建 (输出到 dist/，可直接静态托管或本地打开)
npm run preview  # 预览生产构建 (已开启 --host)
npm run lan      # 构建 + 启动局域网联机服务器 (多人 + 人机同桌)
npm run server   # 仅启动联机服务器 (需已 build)
npm test         # 运行全部单元测试
npm run test:watch   # 监听模式
npm run typecheck    # 仅类型检查
```

> 构建产物为纯静态资源（`base: './'`），可直接双击 `dist/index.html` 离线运行。

## 局域网联机（多人 + 人机同桌）

支持**若干真人 + 若干人机**在同一局域网内同桌对战，无需互联网。架构为「权威服务器」：一台机器作为房主运行 Node 服务器，复用纯逻辑的 `engine/` 与 `ai/` 模块作为唯一裁判，向每个客户端**只下发本人可见的状态**（自己的底牌 + 公共信息，牌堆与他人底牌一律不下发），从根本上避免作弊。

### 开一桌

```bash
# 房主电脑（一条命令搞定，HTTP 与 WebSocket 同端口 8080）
npm run lan          # = npm run build && npm run server
```

启动后终端会打印局域网地址，例如 `http://192.168.1.23:8080`。

1. 房主与其他玩家用浏览器打开该地址（同一 Wi-Fi）。
2. 进入首页点 **「🌐 局域网联机」** → 输入昵称 → 加入。
3. 在**大厅**中各自点空座「坐下」；房主可「+ AI」把空位填成人机、设置盲注/起始码/难度，然后「开始游戏」。
4. 真人玩家行动**没有超时限制**（想多久就多久，只有掉线的玩家会被自动过牌/弃牌以免卡桌）；人机按性格自动行动。
5. **每手结束后暂停**，展示结果与各家盈亏；需**所有在座真人玩家都点「下一手」**才开始下一局（掉线/已离座者不计；设有 120 秒安全兜底，避免有人挂机导致永久卡住）。纯人机桌则短暂停顿后自动继续。

### 特性

- **真人 + 人机混合**：空座可由房主一键填充 AI（复用单机的性格 / 动态诈唬 / 难度系统）。
- **断线重连**：意外断开会在下一手坐出，重连后（同浏览器，凭 token）自动回到原座位继续。若有人掉线后房主选择「返回大厅」，其空位会被自动释放（可重新加入或填入 AI），不会因"幽灵座位"卡住而无法开始下一局。
- **随时可补码（top-up）**：筹码低于买入额时，顶部随时可点「补码」补至买入额——两手之间立即生效；牌局进行中则显示「已申请补码 ✓」，下一手开始时自动生效（符合现金局"牌局中筹码不可变"规则）。输光同样不掉线、不踢回大厅，补码后照常继续；累计盈亏照常统计（补码不计为盈利）。人数不足时牌桌暂停等待补码，而非结束。服务器对所有消息做了异常保护，单次操作出错也不会断开连接。
- **全桌统一的金额显示**：大盲级别与**筹码显示比例（现金$ / 10:1 / 20:1）**均为桌面配置（大厅中房主设置），所有玩家看到完全一致的金额——不会出现房主看筹码数、后加入的玩家看美元的错位。
- **防作弊**：服务器按玩家视角裁剪状态，牌堆与他人手牌永不下发。
- **复用 UI**：联机牌桌复用单机的牌桌、下注交互与「数学参考」面板。
- **逐局确认**：每手结束暂停，所有在座真人「下一手」后才开新局，节奏由玩家掌控。
- 也可在开发模式联机：先 `npm run server`（房主），其他人 `npm run dev:host` 打开 5173 后在「局域网联机」里手动填 `ws://<房主IP>:8080/ws`。

> 实现：`server/`（HTTP 静态服务 + WebSocket 房间状态机），`src/online/`（协议与状态裁剪），`src/ui/online/`（连接 / 大厅 / 联机牌桌）。可用 `npm run typecheck:server` 校验服务器类型。

## 在 iPad / 平板上运行

本项目是纯静态、可离线的 PWA（渐进式 Web 应用），在 iPad 上有三种方式：

### 方式一：部署到静态托管后用 Safari 打开（最省心，推荐）

```bash
npm install && npm run build   # 产物在 dist/
```

把 `dist/` 目录上传到任意静态托管（Netlify 拖拽上传、GitHub Pages、Vercel、Cloudflare Pages 等），在 iPad 的 **Safari** 打开该网址。然后点 **分享 → 添加到主屏幕**，即可像原生 App 一样全屏、离线运行（已内置 Service Worker 预缓存，首次联网打开后即可断网使用）。

### 方式二：同局域网下连电脑的开发/预览服务器（无需部署）

在与 iPad 同一 Wi-Fi 的电脑上运行：

```bash
npm run dev:host        # 或先 npm run build 再 npm run preview
```

终端会显示形如 `http://192.168.x.x:5173/` 的 **Network** 地址，在 iPad Safari 输入该地址即可。同样可"添加到主屏幕"。

### 方式三：用 Capacitor 打包成原生 App，真正离线（如飞机上）

本仓库已内置 Capacitor 配置（`capacitor.config.ts`，`webDir` 指向 `dist`）。原生 App 会把全部网页资源打包进安装包，**完全不依赖网络**，装好后即使飞行模式也能玩。构建 iOS App **必须在 Mac 上用 Xcode**。

**前置条件**：一台 Mac、[Xcode](https://apps.apple.com/app/xcode/id497799835)（App Store 安装）、一个 Apple ID（免费即可，免费签名的 App 有效期 7 天，到期重连 Mac 再运行一次即可；付费开发者账号有效期 1 年）、一根数据线。

**步骤**：

```bash
# 1) 在 Mac 上获取代码并安装依赖
git clone <本仓库地址> && cd TexasPoker
npm install

# 2) 构建网页产物并生成 iOS 原生工程（首次）
npm run cap:add:ios      # = npm run build && npx cap add ios

# 3) 同步资源并打开 Xcode
npm run ipad             # = build + cap sync ios + cap open ios
```

随后在 **Xcode** 里：

1. 左侧选中 **App** 项目 → **Signing & Capabilities** 选项卡。
2. **Team** 选择你的 Apple ID（没有就点 *Add an Account* 登录）；把 **Bundle Identifier** 改成全局唯一的名字，如 `com.你的名字.texaspoker`。
3. 用数据线把 **iPad 连到 Mac**，在 iPad 上点"信任此电脑"。
4. Xcode 顶部的运行目标选择你的 **iPad**（不是模拟器），点 **▶ 运行**。App 会被安装到 iPad。
5. 首次运行 iPad 会拦截：到 iPad **设置 → 通用 → VPN 与设备管理 → 开发者 App**，点信任你的 Apple ID 证书。
6. 回到主屏幕打开 App —— 之后**断网/飞行模式都能离线运行**。
7. 以后更新内容：改完代码 `npm run ipad`，在 Xcode 再 ▶ 运行一次即可。

> 说明：`ios/` 原生工程是按机器生成的（含 CocoaPods 等），已在 `.gitignore` 中忽略，不随仓库提交——在你的 Mac 上首次 `npm run cap:add:ios` 时自动生成。

### 哪种最适合"飞机上离线玩"？

- **没有 Mac / 想最快**：用**方式一或二**——只要在有网时用 Safari 打开一次并"添加到主屏幕"，PWA 会把资源缓存到本地，之后断网（飞机上）照常运行。这是最简单直接的离线方案，无需任何编译。
- **想要装进去、彻底不依赖任何服务器**：用**方式三**做成原生 App，从安装那一刻起就完全离线。

> 提示：界面已做响应式布局，iPad 横屏为左右双栏（牌桌 + 侧边面板），竖屏自动堆叠；下注滑块、快捷按钮、全下二次确认等均支持触控。

## 玩法概览

1. 在开始界面选择**同桌人数 (2~9)**、**大盲级别 ($0.5 / $1 / $2 / $5)**、**买入金额**（按大盲级别折算显示为 $，深度 50/100/150/200 BB）、**难度**。所选买入即进桌现金：大盲 $2、买入 $200 → 进桌就是 $200。
   - **筹码显示**可选 `现金($)` / `10:1` / `20:1`：后两者像真实牌局一样以**筹码数**显示（1 大盲 = 10 或 20 筹码，实际价值由大盲级别决定，如 $1 或 $2）。
   - 牌桌上**庄家按钮（金色 D）**、**小盲（蓝色标签）**、**大盲（橙色标签）**醒目标注。
2. 点击「开始游戏」生成牌桌。每个对手在本桌生命周期内性格固定，可被你观察归纳；**换桌**才会重新生成对手。
3. 轮到你行动时使用底部操作栏：弃牌 / 过牌·跟注 / 加注（滑块 + 1/2 池、3/4 池、底池、全下等快捷按钮 + 键盘快捷键 `F/C/R/A`、`↑↓` 微调）。全下需二次确认防误触。
4. 每手结束后**不会自动跳转**，而是停在最终局面（公共牌、摊牌结果保留），并在侧边「🧠 本手复盘」中给出**逐步骤概率分析**与**每次操作是否合理**的评价；查看完毕点「下一手 →」继续。输光筹码可「补码」。
   - 若你**翻前就弃牌**：本手剩余的 AI 行动会被**快速跑完**（不必等待），随后仍**停在最终局面**并展示「🃏 弃牌牌面分析」——你弃掉的牌、跑完的公共牌，以及"本可获胜 / 弃牌正确（也会输）/ 本可打平"的结论，看完点「下一手」继续。
5. 由于可**补码（rebuy）**，当前筹码不反映胜负历史；每个座位会在筹码下方显示该玩家**本桌累计盈亏**（不含补码，绿涨红跌），联机模式同样显示（牌桌座位 + 侧边座位列表）。

## 学习辅助（练习核心）

- **数学参考面板**（默认隐藏，点「参考」展开）：实时胜率、补牌 outs、转牌/河牌命中率、底池赔率、跟注 EV、当前最佳成牌提示。
- **本手复盘（每手结束自动展示）**：手牌结束后停在最终局面，逐一列出你在翻前/翻牌/转牌/河牌的每个决策点：当时胜率、**底池赔率**、弃/跟/加三选项的 EV 对比、你的实际选择，并给出「合理 / 可改进 / 失误」的评价与文字点评。每个决策点可展开「计算公式」，显示胜率（蒙特卡洛模拟局数与假设范围）、底池赔率 `跟注 ÷ (底池 + 跟注)` 与跟注 EV 的具体代入过程。还会显示**本次投入占筹码比例**，并在「薄边 + 大额投入」时给出**资金管理/风险破产**提示（只看 EV 不够：薄边重注方差大，几次失利即难翻身）。
- **更真实的胜率估计**：胜率不再假设对手持「随机两张」，而是按**当前牌面下最强的前 X% 手牌**为对手建模（面对下注、越大的注、越靠后的街道范围越紧）。这修正了翻牌/河牌「跟注胜率虚高、实战却常输」的问题——对手在池中、尤其下注时的范围远强于随机。
- **考虑对手诈唬（极化范围）**：面对下注时，对手范围按**极化**建模——价值强牌 + 一定比例诈唬（弱牌/破产听牌）。因此你的中等牌（抓诈牌）会得到真实胜率（能赢下那部分诈唬），不再出现「对手河牌诈唬你、系统却显示 0% 胜率」的情况。诈唬比例随牌面湿润度上升、随对手人数（多人池）下降。
- **决策复盘（历史回放）**：在「手牌历史」中打开任意一手回放，逐步骤查看，并对比每个关键决策点的 EV（弃 / 跟 / 加）。
- **手牌历史与回放**：保存最近手牌，支持逐步回放与公共牌渐显。
- **对手行为 HUD**（默认关闭）：开启后在座位旁显示对手 VPIP/PFR/AGG 统计。界面明确提示——开启会降低你亲自观察对手风格的乐趣，是否使用由你决定。
- **📖 教学文档**：游戏页顶部「文档」按钮（开始界面也有入口）打开内置德州扑克教学，含基本规则、位置与起手牌、新手常用技巧、常见牌局分析、进阶技巧（范围思维/极化/尺度/阻断牌/GTO 与剥削/EV 与隐含赔率等），原理与实操并重。

## 三档 AI 难度

| 难度 | 性格分布 | 诈唬 | 位置意识 | 针对你 |
| --- | --- | --- | --- | --- |
| 简单 | 极端易读（岩石/跟注站/疯子） | 很少 | 无 | 否 |
| 中等 | **紧凶/松凶常客各半** | 现金局频率、受控可信 | 强 | 通用范围读取 |
| 困难 | **线下强常客 TAG/LAG** + 混合策略 | 按阻断牌与 EV 选择 | 很强 | **置信度加权画像剥削** |

困难并非简单提高诈唬率：它使用更精确模拟、完整行动线、组合阻断牌及玩家画像；中等保留可信现金局风格，但不会读取持久化画像。

### 困难难度策略详解（含当前参数）

> 以下数值是当前实现的**基准、公式和上下限**，用于模拟有范围意识、会混合策略且会针对熟客调整的线下现金局强玩家，并非声称已经求得 GTO 均衡。最终动作还会受到随机混合、具体手牌组合、位置、有效筹码、行动线和玩家画像共同影响；文中的 `range=0.25`（若公式算出该值）表示按对应规则排序后保留约 25% 的两张底牌组合，不代表每一类牌都以 25% 概率行动。

#### 困难相对中等真正增加了什么

中等和困难共用场景化翻前/翻后主策略；困难不是“无脑多诈唬”，而是提高计算精度并启用长期剥削：

| 参数 | 中等 | 困难 | 原因 |
| --- | ---: | ---: | --- |
| 翻后范围蒙特卡洛 | 480 次/决策 | **720 次/决策** | 降低临界跟注和薄价值的采样噪声 |
| 翻前大额跟注/全下模拟 | 500 次 | **850 次** | 对高方差的大底池使用更稳定的胜率 |
| 最终诈唬频率硬上限 | 0.36 | **0.46** | 困难允许更多合格候选，但仍须通过阻断牌、行动线和 EV 门槛 |
| 跟注概率 sigmoid 温度 | 0.048 | **0.038** | 更贴近数学边界，减少明显 -EV 的随机跟注 |
| 持久化玩家画像 | 不读取 | **读取并按样本置信度加权** | 针对真人长期倾向，而不是偷看底牌 |

#### 1. 固定性格：同桌可观察、换桌才重置

每个困难 AI 创建时有 **38%** 概率生成 LAG、**62%** 概率生成 TAG；字段在“均值 ± spread”内均匀采样并截断到 `[0,1]`。

| 字段 | TAG 范围 | LAG 范围 | 在策略中的主要作用 |
| --- | ---: | ---: | --- |
| `vpip` | 0.205–0.275 | 0.295–0.365 | 翻前整体松紧：`style = clamp(vpip / 0.27, 0.72, 1.4)` |
| `pfr` | 0.725–0.835 | 0.765–0.875 | 保留为性格/兼容字段；困难主路径以显式位置范围代替直接用 PFR 开池 |
| `aggression` | 0.56–0.70 | 0.65–0.79 | 价值加注、隔离、下注尺度与 float 频率 |
| `bluff` | 0.135–0.205 | 0.185–0.255 | 动态诈唬公式的起点，不是最终诈唬率 |
| `callDown` | 0.43–0.57 | 0.49–0.63 | 跟注边际：`edge += (callDown - 0.5) × 0.055` |
| `positionAwareness` | 0.87–0.97 | 0.87–0.97 | 动态诈唬的位置项与非河牌胜率实现修正；翻前位置范围直接由座位决定 |
| `stackReactivity` | 0.79–0.93 | 0.79–0.93 | 深浅筹码 4-bet、听牌隐含赔率 |
| `potReactivity` | 0.77–0.91 | 0.77–0.91 | 底池相对筹码大小对诈唬频率的影响 |

同一手牌的翻前排序还加入 `U(-0.0125,+0.0125)` 小扰动，避免边界组合每次执行完全相同的动作。

#### 2. 翻前手牌排序与场景识别

困难模式使用真实的 **1,326 个组合权重**，对子/同花/非同花分别按 6/4/12 个组合计数，百分位 `pct` 越接近 1 越强。它不是简单的“两张牌点数相加”：

- 对子分数：`52 + (rank - 2) × 4.5`。
- 非对子基础：`(高牌 - 2) × 3.2 + (低牌 - 2) × 1.35`。
- A/K/Q 高牌额外 `+16/+6/+4`；两张 Broadway `+10`。
- 同花 `+9`，非同花 `-9`；相邻/隔一张/隔两张分别 `+18/+7/+3`，大 gap 再扣分。
- A2s–A5s 因坚果同花与轮子潜力额外 `+8`。

行动线被明确分成：

| 完整翻前加注次数 | 场景 |
| ---: | --- |
| 0，且无人 limp | `unopened` |
| 0，已有 limp | `limped` |
| 1 | `singleRaised` |
| 2 | `threeBet` |
| ≥3 | `fourBetPlus` |

首个不足额 all-in 仍会建立一个 raised pot；之后不足额加注不会虚增成 3-bet/4-bet 层级。缺少完整行动历史时，按当前下注级别推断：`≤1.5BB / ≤4.5BB / ≤12BB / >12BB` 分别视为 unopened / single-raised / 3-bet / 4-bet+。

#### 3. 未开池：RFI 与小盲 limp

基础 RFI 是组合比例，实际范围为：

`openRange = clamp(位置基准 × style + stealBonus, 0.08, 0.82)`

| 位置 | 2 人桌 | 3 人桌 | 4–7 人桌 | 8–9 人桌 |
| --- | ---: | ---: | ---: | ---: |
| Early | — | — | 0.19 | **0.145** |
| Middle | — | — | 0.22 | **0.19** |
| HJ | — | — | **0.255** | **0.255** |
| CO | — | — | **0.33** | **0.33** |
| BTN | **0.78** | **0.58** | **0.48** | **0.48** |
| SB | —（BTN 兼任） | **0.42** | **0.42** | **0.42** |

- 除 SB 外采用 **raise-or-fold**；BB 无人加注时直接 check。
- 非单挑 SB（单挑庄家按 BTN 处理）在进入开池范围后，对非 `AA/KK/QQ/AKs/AKo` 保留线下常见的 limp 混合：
  `P(limp) = 0.28 × (1 - aggression × 0.35)`，困难人格下通常约 **20%–23%**。
- RFI 的目标由通用尺度器计算：基准倍数 `2.55 + U(0,0.4)`，取整到 0.5BB 筹码单位后通常为 **2.5BB 或 3BB**，同时受合法最小加注与底池上限约束；深筹码不会 open-jam。

**原因**：前位需要抵御全桌，后位可利用位置和盲注弃牌率；SB 翻后永远 OOP，因此保留少量完成/加注混合，而不是把所有可玩牌机械加注。

#### 4. Limped pot：隔离与 overlimp

| 参数 | 当前公式/数值 |
| --- | --- |
| 隔离范围 | `clamp(位置开池范围 × style + 0.10 + limper数 × 0.018, 0.16, 0.58)` |
| 执行隔离的混合概率 | `0.72 + aggression × 0.22` |
| 隔离基础倍数 | `3.05 + U(0,0.4)` |
| 每个 limper 尺度加成 | `+0.70×` |
| SB/BB OOP 尺度加成 | `+0.45×` |
| 可 overlimp 的结构 | 任意对子、同花 A、gap≤2 的同花连张 |
| overlimp 范围 | `strength ≥ 1 - clamp(baseOpen + 0.18, 0, 0.65)` |

实际目标还会被 pot-cap、最小加注和有效最大投入截断。原因是线下 limp 玩家通常范围宽且愿意看翻牌：价值牌应加大隔离收费，而小对子/同花结构可利用多人池隐含赔率。

#### 5. 面对一次 open：防守、3-bet 与 squeeze

防守范围先取位置基准，再连续响应 open 尺寸：

| 位置 | 防守基准 |
| --- | ---: |
| BB | **0.42** |
| SB | **0.23** |
| 其他 IP | **0.24** |
| 其他 OOP | **0.17** |

完整公式：

```text
defendRange
  = 位置基准
  × exp(-0.20 × max(0, openBB - 2.5))
  × 开池者位置修正
  × style
  × 真人范围修正
  + min(0.08, caller数 × 0.035)

最终 clamp 到 [0.055, 0.56]
```

- 开池者偏后（位置因子 `≥0.72`）时 `×1.18`；偏前（`≤0.42`）时 `×0.78`。
- 若开池者是被画像的真人，再乘 `sqrt(rangeMult)`。
- 因为尺寸项是指数衰减，4.5BB→5BB 只会平滑收紧，不存在“范围断崖”。
- Value 3-bet：对偏后开池使用 top **8.5%**，其他位置 top **5.5%**。
- Light 3-bet 候选只来自 A2s–A5s、高张≥8 且 gap≤1 的同花连张，以及“同花、高张≥J、低张≥9”的结构（如 J9s/QTs/KJs/AQs）；还需位于 top `min(defendRange,0.20)`，混合概率为：
  `bluff × (IP ? 0.55 : 0.38) × foldPressure`。
- 3-bet 目标倍数：IP **2.9–3.3×**，OOP **3.65–4.05×**；每个已跟注者再 `+0.65×` 形成 squeeze，且仍受 pot-cap 限制。
- IP/OOP 优先使用与攻击者的真实行动顺序；上下文缺失时，翻前以 `positionFactor≥0.65` 视为 IP，翻后以 `≥0.60` 视为 IP。

**原因**：BB 已投入 1BB 且通常关闭行动，理应最宽；OOP 需要更大 3-bet 弥补翻后劣势；caller 提供死钱但增加多人风险，因此 squeeze 同时扩大范围收益与尺度。

#### 6. 面对 3-bet：有效筹码驱动的 call / 4-bet

```text
sizePenalty      = clamp(1.15 - max(0, 3betBB - 8) × 0.035, 0.65, 1.10)
shallowPressure  = clamp((70 - effectiveDepthBB) / 40, 0, 1)
deepRealisation  = clamp((effectiveDepthBB - 120) / 180, 0, 1)
depthFactor      = 1
                   - shallowPressure × 0.24 × stackReactivity
                   + deepRealisation × 0.20 × stackReactivity
```

继续范围：

```text
clamp(
  (IP ? 0.13 : 0.105) × sizePenalty × style × depthFactor
  + 可玩深筹码牌奖励,
  0.055,
  0.22
)
```

对子、同花 A、gap≤2 同花连张在深筹码时获得：

`deepRealisation × 0.025 × stackReactivity`

4-bet 参数：

| 决策 | 参数 |
| --- | --- |
| Bluff 候选 | 仅 A2s–A5s |
| Bluff 混合 | `bluff × (0.30 + shallowPressure×0.38 - deepRealisation×0.14) × foldPressure` |
| Value 阈值 | `strength ≥ 0.968 - shallowPressure×0.022 + deepRealisation×0.006` |
| ≤50BB 且已面对 ≥7.5BB | 直接加到有效筹码，通常形成 4-bet jam |
| 常规 4-bet | 基准 `2.15–2.55×`，另受 0.8 pot-cap 和合法最小加注约束 |

**原因**：浅码降低投机牌实现率并把强牌转成 jam/fold；深码允许对子和同花结构多跟注，但 value 4-bet 反而略收紧，以免用边缘成牌打超深大底池。

#### 7. 面对 4-bet+：继续与 5-bet

```text
shallowStackOff = clamp((75 - effectiveDepthBB) / 45, 0, 1)
deepFourBetPlay = clamp((effectiveDepthBB - 160) / 180, 0, 1)

continueRange = clamp(
  0.05 × 真人范围修正
  × (1
     + shallowStackOff × 0.50 × stackReactivity
     + deepFourBetPlay × 0.22 × stackReactivity),
  0.035,
  0.10
)
```

- Value 5-bet 阈值：`0.986 - shallowStackOff×0.018 + deepFourBetPlay×0.004`。
- 5-bet 混合概率：`0.72 + shallowStackOff×0.20 - deepFourBetPlay×0.12`。
- 目标基准 `2.05–2.45×`，允许在合法/有效筹码边界全下；否则继续范围内以 call 为主。

#### 8. 大额下注、全下与隔离

先定义 `effective = max(1, min(本方当前后手, 对局有效后手))`、`currentLevel = 本街已投入 + toCall`。满足下式任一条件时，不再套普通 VPIP/PFR 阈值，而直接模拟对手 shove range：

`toCall ≥ effective × 0.52`，或 `currentLevel ≥ maxRaiseTo`（当前下注已到本方可投入上限，跟注后没有再加注空间）。

| 当前下注级别 | 假设对手最强范围 |
| ---: | ---: |
| ≥55BB | top **4.5%** |
| 30–54.99BB | top **7%** |
| 18–29.99BB | top **11%** |
| <18BB | top **17%** |

- 4-bet+ pot 再 `×0.72`；若相关攻击者是被画像真人，再 `×rangeMult`；最终截断到 `[2.5%,30%]`。
- 困难模式运行 **850 次**范围蒙特卡洛。
- 模拟对手数为 `min(存活对手数, 最后一次加注后的 caller 数 + 1)`：至少包含 shove 者，也纳入已经跟入的玩家。
- 底池赔率：`odds = toCall / (potBefore + toCall)`。
- 继续门槛：`equity + (攻击者为被画像真人 ? valueLean×0.30 : 0) ≥ odds + 0.012`。
- 后面仍有可行动玩家时，合格强牌会隔离：面对 ≥40BB 深 jam 仅 `AA/KK`；较短 jam 可用 `AA/KK/QQ/AKs/AKo`。其他牌即使可合法再加注，也先服从上述 equity gate，避免 KQs 对 100BB jam 变成 200BB 再全下。
- 若任何剩余对手的最大投入都不能超过当前下注，引擎禁止制造无人可匹配的“假加注”。

#### 9. 对手翻后范围：不是“随机两张牌”

当前牌面先把所有合法两张牌按成牌、踢脚和听牌潜力排序，再从估计范围抽样。

**当前街范围比例**：

```text
基础：面对下注 0.38；无人下注 0.62
下注尺度：- min(0.18, min(2, betToPot) × 0.12)
同街已有 ≥2 次激进动作：×0.72
3-bet pot：×0.82
4-bet+ pot：×0.65
limped pot：×1.18
turn：-0.04
river：-0.08
基础函数 clamp [0.12,0.85]
check-raise：再 ×0.62
困难决策最终 clamp [0.07,0.88]
```

**翻前范围连续带入**：

| 翻前底池 | 保留组合比例 |
| --- | ---: |
| 4-bet+ | **0.055** |
| 3-bet | **0.12** |
| Single-raised，相关攻击者偏前 | **0.19** |
| Single-raised，相关攻击者居中 | **0.26** |
| Single-raised，相关攻击者偏后 | **0.34** |
| Limped / 未加注 | **0.72** |
| 无法分类但已加注 | **0.30** |

“相关攻击者”优先指本街最后攻击者；本街无人进攻时回看上一街最后攻击者。最终截断到 `[0.035,0.86]`；若该攻击者是被画像真人，会乘其 `rangeMult`。

**下注范围的诈唬份额**：

```text
base = 0.30 + boardWetness × 0.10
betToPot ≥ 0.8：+0.05
river：+0.02
同街 ≥2 次激进动作：×0.70
多人：÷ sqrt(liveOpponents)
基础 clamp [0.08,0.50]
check-raise：再 ×0.62
画像大小注读牌后，最终 clamp [0.03,0.50]
```

无人下注时基础函数返回 0，决策层最终保留 **0.03** 的范围尾部下限；画像读数只在面对被画像真人下注时介入。

多人池不会把所有人都当成同一个下注者：一个玩家来自极化下注范围；已跟注者来自位于 value range 下方约 **35% 组合**的 capped range；尚未行动者保留较宽翻前范围。这样不会因为“三个对手都被假设为顶端下注范围”而过度弃牌。

范围排序本身是启发式模型：

- `rangeFraction` 输入截断到 `[0.02,1]`，翻前连续范围截断到 `[0.03,1]`。
- Value pool 至少保留 `max(12, 对手数×6)` 个组合；bluff pool 最多从 value range 之外按候选质量选取 `max(对手数×6, 全组合×40%)`。
- 成牌分数：`牌型类别×110 + 踢脚分 + 听牌分`。
- 翻牌/转牌听牌分：坚果同花听牌 `+78`、其他同花听牌 `+66`、两头顺 `+58`、卡顺 `+30`、每张 overcard `+7`。
- 河牌诈唬候选：A/K 同花阻断分别 `+60/+35`，匹配对子牌面 `+25`，持 A `+8`，再按现有成牌类别 `-35×类别`，优先“阻断坚果但没有摊牌价值”的组合。
- 同一公共牌的组合排序放入 **12 个 board 的 LRU 缓存**，避免移动端每次决策重复排序约千个组合。

#### 10. 真实听牌、阻断牌与牌面湿润度

AI 明确区分顶对/中对/底对/口袋超对、同花听牌、坚果同花听牌、卡顺、两头顺和组合听牌。只会让玩家底牌真正改善牌力的顺子牌才算 outs；“公共牌自己成顺”不会被误认为 8 个干净 outs。

`boardWetness` 范围为 `[0,1]`：

| 牌面特征 | 加分 |
| --- | ---: |
| 三张及以上同花 | +0.45 |
| 两张同花 | +0.20 |
| 相邻 rank / gap 2 / gap 3 | 每处 +0.18 / +0.12 / +0.06 |
| 对子牌面 | +0.15 |
| 连通部分上限 | 0.40 |

`blockerScore`：

- 三张及以上同花牌面持该花色 A/K：`+0.55/+0.30`。
- 对子牌面且底牌持该 rank：`+0.25`。
- 任意 A：`+0.08`；总分截断到 1。

`showdownValue`：超对/顶对/中对/其他一对分别 `0.58/0.50/0.38/0.30`；A-high `0.16`，其他高牌 `0.06`；更强成牌按牌型类别归一化。

```text
bluffQuality
  = blockerScore × (river ? 0.75 : 0.25)
  + 同花听牌 (坚果 0.45；其他 0.32)
  + 顺子听牌 (两头 0.35；卡顺 0.20)
  + 组合听牌 0.18
  + overcard数 × 0.06
  - showdownValue × (river ? 0.55 : 0.25)

最终 clamp [0,1]
```

近似 outs 为同花 9、两头顺 8、卡顺 4、高牌状态每张 overcard 3，总上限 **15**。

#### 11. 动态诈唬频率：候选质量优先

第一层以固定性格的 `bluff` 为起点：

```text
dynamicBluff
  = bluff
  + positionAwareness × (positionFactor - 0.5) × 0.40
  + boardWetness × 0.25
  - (liveOpponents - 1) × 0.12
  + (0.5 - min(1, pot / stack)) × 0.15 × potReactivity
  - (recentImage - 0.3) × 0.35

river 再 ×0.85；输出 clamp [0,0.8]
```

第二层只保留合适组合：

```text
candidateMultiplier
  = clamp(0.18 + bluffQuality×1.15 - showdownValue×0.28, 0.05, 1.05)

bluffFrequency
  = dynamicBluff × exploit.bluffMult × candidateMultiplier
```

多人池再 `×0.72`，困难最终上限 **0.46**。因此上限更高不等于随便开火：无阻断、无听牌且有摊牌价值的牌会被大幅降频，负 EV 动作仍被拒绝。

#### 12. 价值阈值、跟注与动作 EV

价值基准：

```text
valueThreshold = min(0.82, 0.55 + (对手数 - 1) × 0.07)
valueThreshold -= clamp(recentImage - 0.3, 0, 0.4) × 0.10
```

- `nutRange`：模拟胜率 `≥0.88`，且至少两对，或持顶对/超对。
- `strongValue`：胜率达到 valueThreshold，且至少一对；河牌也允许纯 equity 判定的极少数特殊组合。
- 多人池每多一名对手，价值门槛提高 7 个百分点，上限 82%。

面对下注：

```text
directOdds = toCall / (potBefore + toCall)

真实听牌的深筹码折扣：
depth = clamp((SPR - 2) / 6, 0, 1)
impliedDiscount
  = depth × (IP ? 0.12 : 0.07) × (干净听牌 ? 1 : 0.62)
needed = directOdds × (1 - impliedDiscount × (0.55 + stackReactivity×0.45))

edge
  = equity - needed
  + (callDown - 0.5) × 0.055
  + 非河牌位置修正
  + 真人剥削 valueLean

continueProbability = sigmoid(edge / 0.038)
```

非河牌位置修正为 `positionAwareness × (positionFactor - 0.5) × 0.055`；河牌不再凭空奖励位置。若 `directOdds≤0.15 && equity>0.17`，继续概率至少 **0.86**，避免面对极小注过度弃牌。

诈唬下注/加注必须满足：

```text
calledEV = equity × (pot + heroRisk + callerContribution) - heroRisk
actionEV = foldEquity × pot + (1 - foldEquity) × calledEV
```

这里区分“本方为加注先补齐的金额”和“对手面对加注需要补齐的金额”，不会把两者错误视为相等。

弃牌率近似：

```text
基础：主动下注/刺探 0.39；面对下注的诈唬加注 0.30
IP：+0.05
每多一名对手：-0.10
尺寸：+ clamp(size-0.5, -0.25, 0.65) × 0.13
阻断牌：+ blockerScore × 0.08
面对 check-raise：-0.16
同街已有 ≥2 次激进动作：-0.10
再乘真人 foldPressure；最终 clamp [0.08,0.72]
```

#### 13. 牌面、SPR 与下注尺度

极化价值与诈唬共用同一套尺寸模型，薄价值走非极化小尺寸桶，避免“某个尺寸永远是 bluff”的机械马脚：

| 街道/场景 | 底池比例 |
| --- | --- |
| Flop：对子面或 `wetness<0.22` | **0.30 pot** |
| Flop：湿润面 | `0.48 + wetness×0.28` |
| 3-bet/4-bet flop | 上述结果 `-0.08` |
| Turn 非极化 | `0.52 + wetness×0.28` |
| Turn 极化 | 再 `+0.10` |
| River 薄价值 | **0.34 pot** |
| River 极化 | `0.72 + blockerScore×0.18` |
| 多人池 | `+0.08` |
| 性格修正 | `+(aggression - 0.6)×0.08` |

SPR≤3 时，用剩余街道数（flop 3、turn 2、river 1）计算几何尺度：

`geometric = ((1 + 2×effectiveStack/pot)^(1/streets) - 1) / 2`

并取原尺度与 `min(1, geometric)` 的较大值。Turn/River 极化范围若至少成同花或 `blockerScore≥0.45`，有 **18%** 混合到 `1.05–1.25 pot` overbet。最终再加入 `±0.04 pot` 抖动并截断到 `[0.25,1.25]`。

面对下注的加注倍数：

| 类型 | IP 基准 | OOP 基准 |
| --- | ---: | ---: |
| 价值加注 | 2.7–3.1× | 3.2–3.6× |
| 半诈唬加注 | 2.75–3.15× | 3.25–3.65× |
| 阻断牌诈唬加注 | 2.8–3.2× | 3.3–3.7× |

通用尺度器还会取以下两者较小值，防止 raise war 指数膨胀：

```text
xBetTarget = currentLevel × (xBetBase + U(0,0.4) + squeezeBonus)
potCap      = currentLevel + potAfterCall × max(fraction,0.5) × U(0.9,1.1)
```

只有 `effectiveRemaining ≤ potAfterCall×1.1` 才视为低 SPR commit spot；允许全下时，若目标已达到最大投入的 **90%**，直接推完而不留零头。

主动价值下注只有在 commit 且 `equity≥0.72` 时主动开启该全下补齐；面对下注的价值加注对应门槛为 `equity≥0.70`（被最小加注规则强制到上限的情况除外）。

#### 14. 行动线混合：trap、float、barrel 与诈唬加注

| 场景 | 必要条件与当前参数 |
| --- | --- |
| 强价值主动下注 | `equity≥valueThreshold`；flop/turn 还须至少一对，river 可仅凭 equity；若不 trap 则下注 |
| 顶对/超对保护下注 | flop/turn 且 `equity≥max(0.40,valueThreshold-0.16)`；混合概率见下式 |
| Trap | 真人激进画像可 `+0.20`；`boardWetness<0.48`、两对+、OOP 且上一街对手主导再 `+0.12` |
| 面对下注 trap-call | `trapMore` 已启用、`equity≥valueThreshold+0.08`、尚未 commit 时，以 **42%** 混合只跟不加 |
| Flop range c-bet | AI 是翻前最后攻击者、候选合格、`actionEV>0`；按牌面/人数/位置混合，硬上限 **58%** |
| Float / checked-to stab | 上一街对手是攻击者、**本街已真实 check 到 AI**、AI 上街不是攻击者、对手数≤2、`actionEV>0` |
| Float 概率 | `clamp((0.28 + (IP?0.20:0) + aggression×0.12) × foldPressure × (0.45+bluffQuality), 0, 0.72)` |
| Checked-through probe | flop 或 turn 全桌过牌后，下一街按位置、人数和候选质量主动 probe；`actionEV>0`，硬上限 **62%** |
| 延续 barrel | AI 上一街确实以 bluff 身份进攻，且当前不面对 check-raise、`actionEV>0` |
| Barrel 概率 | `(river?0.34:0.52) + J/Q/K/A runout 0.08 + bluffQuality×0.18`，再乘 `bluffMult`，上限 **0.72** |
| 面对下注的 value raise | `equity ≥ valueThreshold+0.08`、至少一对，混合概率 `0.48 + aggression×0.32` |
| 继续区 semi-raise | 真实听牌且 `bluffQuality≥0.35`、EV>0，混合 `bluffFrequency×0.72` |
| 弃牌区 bluff-raise | river `bluffQuality≥0.35`，其他街 `≥0.45`；`toCall≤0.7pot`、EV>0，混合 `bluffFrequency×0.35` |

保护下注概率：

```text
clamp(
  0.36 + aggression×0.34 + boardWetness×0.10
  - (opponents-1)×0.07 + (IP ? 0.05 : 0),
  0.25,
  0.78
)
```

Flop range c-bet 只从真实听牌、`bluffQuality≥0.08` 或 `showdownValue≤0.30` 的组合中选择；顶对/超对先走上述保护下注混合。其频率为：

```text
cbetBase
  = 0.28 + aggression×0.22 + (IP ? 0.08 : 0)
  + (3-bet/4-bet+ pot ? 0.08 : 0)
  - (opponents-1)×0.08 - boardWetness×0.08

cbetQuality
  = clamp(0.52 + bluffQuality×0.50 + (有overcard ? 0.05 : 0), 0.45, 1)

P(c-bet) = clamp(cbetBase × cbetQuality × foldPressure, 0.04, 0.58)
```

Turn/River 若上一街至少两人行动且全部 check，则标记为 `previousStreetCheckedThrough`。Turn 可用听牌、高牌、底/中对和公共牌对子 probe；river 仅用高牌候选。当前混合为：

```text
probeBase
  = 0.20 + aggression×0.22 + positionFactor×0.18
  - (opponents-1)×0.065 - (river ? 0.03 : 0)

probeQuality
  = 一对时 0.75
  : clamp(0.66 + bluffQuality×0.42 - showdownValue×0.18, 0.55, 1)

P(probe) = clamp(probeBase × probeQuality × foldPressure, 0.06, 0.62)
```

全桌过牌会使范围封顶，因此 probe 的弃牌率估计再增加 `0.08 + positionFactor×0.04`，最终仍截断到 `[0.08,0.78]`。Range c-bet、保护下注和 checked-through probe 都使用非极化尺度桶，并继续服从动作 EV；这提高真实主动进攻率，但不会让多人池变成无条件轮流诈唬。

若上一街 bluff barrel 变成负 EV，AI 会明确进入 give-up check，而不是为了“讲故事”继续烧钱。

#### 15. 置信度加权的真人画像剥削（仅困难）

单机保存一份真人画像；局域网按真人座位分别维护。多人池只把当前/上一街相关真人攻击者的画像用于本次决策；没有明确攻击者时，只有 heads-up 才使用唯一真人作为 fallback，避免把无关玩家倾向套到 AI-vs-AI 行动。

**贝叶斯统计**：

| 指标 | 先验 | 先验权重 |
| --- | ---: | ---: |
| VPIP | 0.30 | 8 手牌 |
| PFR | 0.18 | 8 手牌 |
| Fold to steal | 0.50 | 5 次机会 |
| Aggression | 0.50 | 10 个动作 |
| 河牌弱牌下注率 | 0.30 | 5 次摊牌下注 |
| Went to showdown | 0.30 | 8 手牌 |
| Fold to c-bet | 0.50 | 5 次机会 |

统一更新公式：`(命中数 + prior×priorWeight) / (机会数 + priorWeight)`，避免一次观察就产生 0% 或 100% 读牌。

空画像在尚无任何手牌时展示 PFR 初值 **0.15**；第一手结束后即按上表的 **0.18/8** 贝叶斯先验统一更新。

- Steal 只统计 unopened pot 中 CO/BTN/SB 对盲位的首个 open；limped pot isolation 不算偷盲。
- C-bet 只统计翻前最后攻击者在 flop 的下注及真人回应。
- 河牌“弱牌下注”只在摊牌后确认：高牌或只能玩公共牌才记为 weak；输掉的顶对/薄价值不算诈唬。
- 大河牌下注定义为 `本次投入 > potBefore×0.55`，大小注分别记录。

**置信度**：

```text
总权重     = clamp(hands / 36, 0, 1)
偷盲权重   = 总权重 × clamp(stealFaced / 8, 0, 1)
c-bet权重  = 总权重 × clamp(cbetFaced / 10, 0, 1)
行动权重   = 总权重 × clamp((aggressive+passive) / 35, 0, 1)
blend(raw,w)= 1 + (raw-1)×w
```

**具体剥削**：

| 真人倾向 | 困难 AI 调整 |
| --- | --- |
| `foldToSteal>0.60` 且 AI 位置因子>0.55 | `stealBonus=(foldToSteal-0.60)×0.60×偷盲权重` |
| `foldToSteal>0.55` | 诈唬乘数向 **1.30×** 混合 |
| `wentToShowdown>0.45` | 诈唬乘数向 **0.60×** 混合 |
| `aggression>0.60` | 诈唬乘数向 **0.80×** 混合；`valueLean += 0.05×行动权重`；行动权重>0.30 时允许更多 trap |
| Fold to c-bet | `bluffMult ×= blend(1+(foldToCbet-0.5)×0.9, cbet权重)` |
| 综合弃牌压力 | `blend(1+(foldToCbet-0.5)×0.7+(foldToSteal-0.5)×0.4, max(cbet权重,偷盲权重))` |
| 真人翻前松紧 | `observedRange=clamp((VPIP/0.28)×0.45+(PFR/0.18)×0.55,0.65,1.65)`，再按总权重向 1 混合 |

河牌至少有 **4 次**对应尺度的摊牌下注后，诈唬读数才启用：
`read = clamp((weak/shown)/0.33, 0.35, 1.8)`，再按总权重向 1 混合。大注/小注样本不足时回退到总体读数。

历史样本以 `本次投入 > potBefore×0.55` 区分大注；实际决策在当前 `betToPot≥0.70` 时调用大注读数，否则调用小注读数。

#### 16. 自我形象、思考时间与规则保护

- AI 激进形象初值 **0.30**；每手结束更新：
  `image = 0.65×旧值 + 0.35×本手(激进行动 / 全部非弃牌行动)`。
  形象越疯，诈唬越少；最高可让价值阈值下降 4 个百分点，以便被更宽跟注时扩大价值。
- 基础思考时间 **350–1050ms**；弃牌、跟注或代码标记为 `tough` 的复杂决策额外 **0–700ms**，所以单机常规模式理论范围为 **350–1750ms**。联机服务器再截断到 **450–1600ms**，避免瞬间动作或长时间拖桌；单机快速模式会进一步缩短等待。
- 单次不足额 all-in 不会重开已经行动者的加注权；多个不足额 all-in 的**累计增量达到一个完整最小加注**时会正确重开。
- all-in 金额不超过应跟金额时记录为 call；后续范围不会误判为 raise。
- 后续不足额加注不虚增 3-bet/4-bet 层级；无人能投入超过当前下注时禁止继续加注。
- 过期 AI 决策或异常联机消息若请求非法 bet/raise/all-in，会安全降级为 call/check/fold，避免牌桌死循环。

这些参数共同服务于一个目标：**先像强常客一样选范围与尺度，再用少量混合避免可读，最后只在有足够样本时针对真人偏差做剥削**。

### 货币模型

为保证边池/分配全程整数运算精确，内部以**小盲为最小单位**：`SB = 1 chip`、`BB = 2 chips`、100 BB = 200 chips。所选大盲级别（0.5/1/2/5）作为展示用货币倍率——界面金额均以美元符号显示：选大盲 2 时，大盲注显示 $2、小盲 $1、100 BB 起始码显示 $200（联机时跟随房主设置的级别）。

## 关键算法设计说明

- **牌型评估器**：将一手 5 张牌编码为单个可比较整数 `category * 15^5 + tiebreakers`（base-15 保证 JS 双精度内精确），`O(1)` 比较；7 张牌中枚举出最佳类别并正确处理踢脚、轮子顺子（A-2-3-4-5）与平局。
- **边池分配器**：纯函数。按「最小非零下注档位」逐层剥离，弃牌者的死钱保留在池中但不参与争夺；分配时按 7 张最佳牌定胜负，平分后的奇数筹码从 button 左侧最近的合资格玩家开始逐枚发放。
- **蒙特卡洛**：移除已知牌后随机发对手手牌与公共牌跑若干局；通用 `range` 模式在不重复发牌的前提下做有限候选采样，困难 AI 则使用当前牌面的组合排序、极化诈唬池、capped caller 与未行动玩家范围。可注入种子随机源以便复现测试。
- **下注规则**：完整实现最小加注校验；单个不足额 all-in 不重开加注权，但多个不足额 all-in 的累计增量达到完整加注时会重开；同时支持跟注/过牌/加注/全下、盲注轮转与翻前翻后行动顺序（含单挑特例）。
